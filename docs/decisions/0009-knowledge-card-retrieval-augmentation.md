# 0009 知识卡片作为派生检索单元，检索增强按评测逐项启用

- 日期：2026-11-10
- 状态：已采纳，S0/S4 待验证

## 背景
现有方案（product-plan §8）只索引原文 chunk：关键词路（jieba + `simple` tsvector）与语义路（百炼 Embedding）经 RRF 融合。该基线在本产品的材料形态下有几类可预见的短板：

- **短材料信息量低**：一句想法、一张截图的 OCR 碎片，缺少主题词，用户的查询用词与原文用词经常对不上。
- **长文 chunk 脱离上下文**：网页切块后，单块不含标题和主题，关键词路与语义路都难以命中"这篇文章在讲什么"。
- **查询粒度错位**：用户常问"我收藏过的那篇讲 XX 的文章"，这是资料级问题；逐块检索对资料级问题召回不稳。
- **个人备注与资料分离**：备注常包含用户自己的分类词，原方案只在 EntryRevision 中保存，未参与检索。

同时，ingestion 流程已计划为每条资料生成标题和摘要（light 档，ADR 0002），这一步可以低成本地多产出一些结构化字段。

## 决策

### 1. 知识卡片（KnowledgeCard）
每个 EntryRevision 在 ingestion 中生成一张卡片，作为 Artifact 的一种（`kind = card`）。卡片沿用原计划的标题/摘要调用（同一次 light 调用、同一 JSON schema），不增加独立模型调用。

| 字段 | 说明 |
|---|---|
| title | 自动标题（已在原计划中） |
| summary | 1–3 句摘要（已在原计划中） |
| key_points | ≤5 条要点，每条带来源 chunk 序号 |
| keywords | ≤8 个主题词/实体，含中英文原样写法 |
| questions | ≤3 个"这条资料能回答的问题"（仅用于检索，见 §3） |
| kind_hint | 观点 / 事实 / 教程 / 数据 / 个人想法 |

约束：

- **卡片是派生物，不是证据。** 问答引用仍只能指向原文 chunk 与 EntryRevision；卡片内容不进入引用契约（product-plan §8.3），回答提示词中卡片只作为导航上下文，与"当前总结"同级。
- 卡片绑定 `entry_revision_id`、`owner_id`、`prompt_version`、`index_version`；新版本生成新卡片，旧卡片随旧版本失效。
- 卡片生成失败不影响"已可检索"：原文 chunk 索引完成即进入"已可检索"，卡片属于"整理完成"阶段（product-plan §3.4）。
- 卡片属于 AI 派生物，不产生 ProjectEvent，不触发总结（product-plan §4.3）。
- 删除生命周期同 Artifact：删除资料时卡片与其向量一并清理（S6）。
- 首版用户不可编辑卡片；资料详情展示卡片的标题、摘要、要点、关键词，标注"AI 整理"。用户修正走"编辑备注/修正正文 → 新版本 → 重新生成"。

### 2. 检索增强：分层启用

| 编号 | 增强 | 成本 | 首版处置 |
|---|---|---|---|
| R1 | **上下文 chunk 头**：每个 chunk 写入索引前拼接 `资料标题 · 章节标题 · 个人备注摘录`，tsvector 与 Embedding 都用拼接后的文本；展示与引用仍用原文 | 无额外模型调用；略增 token | **默认启用**，S0 与基线对比 |
| R2 | **卡片路**：卡片（title + summary + keywords + key_points）作为资料级检索单元，单独一行 Chunk（`unit = card`），参与关键词与语义两路，RRF 时按 entry 合并后展开到该资料得分最高的原文 chunk | 每条资料 +1 次 Embedding | **默认启用**，S4 用评测决定权重 |
| R3 | **假设问题（doc2query）**：卡片的 `questions` 并入卡片路索引文本 | 无额外调用 | 随 R2 做消融，命中提升 < 1 题则关闭 |
| R4 | **查询改写 / HyDE**：问答前用 light 模型改写或生成假设答案再检索 | 每次查询 +1 次模型调用与延迟 | **不进首版**，仅在 R1–R3 后仍未达 16/20 时评估 |
| R5 | **Reranker** | 新依赖与延迟 | 维持原决定，不进首版 |
| R6 | **多轮检索** | 每轮 +1 次检索与模型调用 | 维持原决定：S4 验证需要时至多两轮 |

检索流程（S4）：

```text
owner（+ project）过滤
 → 关键词路：chunk(R1) ∪ card(R2/R3)
 → 语义路：chunk(R1) ∪ card(R2/R3)
 → RRF 融合 → 按 entry 聚合（card 命中映射到该 entry 最佳原文 chunk）
 → Top K 原文 chunk 作为证据；对应卡片作为导航上下文
```

### 3. 不采纳
- **以卡片替代原文 chunk**：摘要丢细节，且引用必须定位原文。
- **用户可编辑的原子笔记（Zettelkasten 式卡片盒）**：与"个人想法/备注""正式决定"语义重叠，首版不引入新的用户可写对象。
- **卡片间自动链接 / 知识图谱**：与关联建议（product-plan §3.7）重叠；Graphiti / LightRAG 维持 product-plan §15 的重评条件。

## 后果
- Artifact/Chunk 表需要 `unit`（chunk / card）字段和 `context_header_version`；索引文本与展示文本分开存储（`index_text`、`display_text`）。
- 标题/摘要提示词扩展为卡片 schema；JSON 合法率与字段正确率纳入 ADR 0002 的 S0 选型样本。
- 卡片与 R1 头部一旦变更，属于索引版本变化，需要后台回填；`index_version` 规则同 ADR 0001。
- 评测记录（docs/evaluation）增加消融维度：基线 / +R1 / +R1+R2 / +R1+R2+R3。
- 引用契约不变；"卡片不是证据"需要单元测试：回答中引用卡片 ID 的情况被引用校验拒绝。
