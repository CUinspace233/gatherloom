# 0004 网页正文由 Safari 分享扩展预处理获取

- 日期：2026-11-09
- 状态：已采纳

## 背景
服务器位于海外（ADR 0007）。微信公众号、知乎等常见中文来源存在反爬、登录墙或 JS 渲染，服务端抓取成功率低。

## 决策
- 分享扩展配置 `NSExtensionJavaScriptPreprocessingFile`，在 Safari 中读取已渲染页面的 URL、标题、规范链接、正文（Readability 类提取）及抓取时间，作为 `client_extract` 加工版本随提交上传。
- 服务端抓取作为补充：客户端未提供正文、正文过短，或用户请求重新抓取时执行；保留原方案全部 SSRF 防护。
- 两者都失败时显示状态，允许用户粘贴正文。

## 后果
- 客户端提取的正文是不可信内容：服务端做大小（≤100,000 字符）、编码与 HTML 清洗校验，只作为模型上下文中的资料。
- 引用定位到保存的正文快照，标注来源为"分享时页面快照"。
- 非 Safari App 的分享只得到 URL，走服务端抓取。

## 2026-11-16 补充：Firecrawl 兜底

- 服务端兜底使用 Firecrawl v2 `/scrape`，服务器只访问固定的 Firecrawl API，不直接请求目标网页；Safari 正文非空时不调用。
- 通过 `GATHERLOOM_FIRECRAWL_API_KEY` 启用；新链接自动提取，Scheduler 每轮最多入队 50 条缺正文的旧链接。额度由 Firecrawl 独立计费。
- `EntryRevision.server_extract` 保存首次成功的正文快照，与 `client_extract` 分开。读取正文、分块、知识卡片、历史版本和引用使用同一快照，仅修改备注时复用。
- 请求 `onlyMainContent=true`、`storeInCache=false`；保存正文上限仍为 100,000 字符。网络和限流等错误按现有任务机制退避，鉴权、额度和无效内容错误需要人工处理。
- 补读失败保留已有索引；成功后重建当前版本的索引与卡片。扫描标记与任务 generation 防止重复扫描无限重试，快照提交后重放不重复调用。外部调用成功与本地提交之间崩溃仍可能再次调用，不承诺 Firecrawl 计费严格一次。
- 本版本不加入服务器直连抓取；原来规划的直连 DNS/重定向 SSRF 校验保留为该能力将来的前置条件。
